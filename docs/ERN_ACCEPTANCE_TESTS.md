# ERN 受け入れテスト設計（E1〜E13）

対象: ERN（専門度・貢献量・信頼度の3エンジン＋find_expert。SPEC_phase3）。
根拠: SPEC_phase3 §0 の原則、不変条件 INV-1/INV-5/INV-7（SPEC_phase1 付録）、§3.3。
方針: T1〜T10・S# と同じく **InMemory ストアでオフライン実行**（tests/conftest.py 拡張）。
ERN を変更したら、該当する E# が green であることを示すこと。

## 出力の非評価性（INV-5）

- **E1 出力スキーマに数値評価が無い**: find_expert の戻り値（および将来のツール出力）に
  `score` / `rank` / `rating` / `order` 等の比較可能な数値フィールドが存在しない。
  テスト: 戻り値を再帰走査し、候補オブジェクトのキー集合が許可リスト
  （person_id, display_name, evidence, evidence_type 等）に限定されることを表明。
- **E2 上限3名・順不同**: 候補は最大3名。並びが「良い順」を意味しないことを構造で保証
  （例: 内部選定順をそのまま出さない — シャッフルまたは person_id 順の固定ソートで
  内部スコア順を破壊していることをテストで観察）。
- **E3 DDLに順位・総合スコア列が無い**: ERN 新規テーブルの DDL文字列に
  `rank` / `score` 列が無いことを grep 表明(T10 と同型の SQL 検査)。

## 同意分離（INV-7）

- **E4 未同意者は絶対に出ない**: consent_internal=false の人物は、シグナルが最強でも
  候補に出ない。**両ゲートで**検査 — (a) InMemory 経路の出力 (b) BigQuery 用 WHERE 句の
  文字列に consent 条件が含まれること（§3.3 二重ゲートと同型）。
- **E5 オプトアウト即時反映**: consent を false に変更した直後の find_expert 呼び出しで
  当人が消える（キャッシュで残らない）。
- **E6 サイレント非対称開示**: 検索イベントは監査証跡に記録されるが、
  (a) 候補者側に通知する経路が存在しない (b) 「誰が探したか」を返すツールが存在しない。
  テスト: ServerContext の公開メソッドを走査し、検索者情報を露出する戻り値が無いこと。

## シグナルの監査証跡性（信頼度エンジン）

- **E7 append-only**: シグナルストアに update/delete API が無い（メソッド一覧の表明）。
  同一イベントの再記録は2行になり、カウントは導出値（集計）として増える。
- **E8 逐語なし（INV-1）**: シグナルイベントのモデル・行マッパー・DDL に
  prompt/raw_text/transcript 相当のフィールドが無い（T6 と同型の4点検査）。

## 鮮度・コールドスタート

- **E9 半減期は設定値**: 半減期180日がロジック内リテラルでなく config 由来。
  テスト: 設定を変えると内部選定が変わる（外部出力に数値は出さないまま、
  候補集合の変化で観察する）。
- **E10 根拠種別の明示**: シグナルゼロ領域では役職ベースのフォールバックが働き、
  evidence_type="役職ベース" が出力に付く。シグナルが存在する領域では
  evidence_type="実績ベース"。混在時も候補ごとに正しく付く。

## ACL・依存の切断（先読み制約）

- **E11 スコープ判定は acl.py 経由のみ**: ERN 新規モジュールのソースに
  tier/audience 語彙（"personal"/"team"/"dept"/"org"/"S0".."S5" のような段階名 等）の文字列比較が
  直書きされていない（grep 表明）。可視性は retrieval/acl.py の関数呼び出しに限定。
  三色語彙のハードコード禁止も同じテストで grep する（CI の pytest で実行される）。
- **E12 circles 非依存・計器盤搭載**: (a) ERN モジュールが circles を import しない
  (b) find_expert 呼び出しが**計器盤（`tool_events`）**に載る。
- **E13 台帳が開示経路にならない**: E12(b) の記録に**候補者名・person_id を含めない**
  （含めると「誰が誰を探したか」が読める記録になり、E6 の非対称開示を台帳経由で破る）。
  テスト: find_expert 起因の `tool_events` 行に候補者識別子も topic 本文も無いこと。

  > 記録先が `usage_log` ではなく `tool_events` である理由は SPEC_phase3 §4f の注を参照。

## テストの配置

- E# は `tests/test_e01_…py` 〜の命名で1ファイル1観点。ERN 用の InMemory フィクスチャ
  （シグナルストア・consent 付き persons）は `tests/conftest.py` にある。
- 「出力に数値を出さない」系（E1）はツールを足すと破られやすい。スキーマの許可リストは
  共通ヘルパ（`ern/schema.py`）にあり、全 ERN ツールに適用する。
